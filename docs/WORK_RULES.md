# docs/WORK_RULES.md — HWPX 양식 채움 작업 규칙

이 문서는 현재 프로젝트의 작업 분담과 기본 규칙을 정리한다.
상세 설계와 처리 흐름은 PROJECT_BLUEPRINT.md와 루트 SKILL.md를 따른다.
충돌이 생기면 루트 SKILL.md의 절대 규칙을 우선한다.

## 작업 폴더와 수정 경계

- 두 담당자는 각자 별도 작업 폴더를 사용한다.
- 각자는 자기 담당 영역의 파일만 수정한다.
- 상대 담당 파일을 임의로 수정하지 않는다.
- 공통 계약 변경이 필요하면 먼저 공유한다.
- 공유 전에는 한쪽이 다른 쪽 영역을 건드리지 않는다.

## 자료와 원본 보존

- 현재 저장소 안의 자료만 사용한다.
- 예선 원본과 기존 변경은 보존한다.
- `reference/qualifier` 아래의 예선 원본은 수정하지 않는다.
- 기존 변경 내역을 지우거나 덮어쓰지 않는다.

## 키 file 처리

- 키 file은 삭제하지 않는다.
- 키 file의 내용을 화면에 출력하지 않는다.
- 키 file은 Git 추적에서 제외한다.
- 키 존재와 실제 연결 성공은 같은 것으로 보지 않는다.

## 검사 기록 원칙

- 실제로 실행한 검사만 결과로 기록한다.
- 미실행, skip, 실패는 통과로 표시하지 않는다.
- 빈 값만 반환하거나 품질을 낮춰 통과로 기록하지 않는다.
- 자동 결과와 수동 수정 후 결과는 따로 기록한다.
- 워크 규칙이 구현 완료나 테스트 통과를 뜻하지 않는다.

## 검토 기준

- A는 표·문단·서식·고정 문구를 그대로 보존한다.
- B는 HWPX·TXT·Markdown·붙여넣기 내용에서 근거 있는 내용만 입력란에 채운다.
- 예선의 "A 문장 제거" 규칙과 "B 구조 그대로 유지" 규칙은 적용하지 않는다.
- Solar는 내용 연결만 판단한다.
- 실제 편집과 검증은 규칙 기반 엔진이 맡는다.
